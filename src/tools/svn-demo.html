        📖 SVN 常用命令速查
        

        
      

      

        
每天都会用到

        

          
svn checkout <URL> [目录]检出工作副本。缩写 co，一个项目只做一次

          
svn update把版本库的新内容拉到本地。缩写 up，开工第一件事

          
svn status看本地改了什么，不联网。缩写 st；加 -u 顺便跟服务器比一下

          
svn add <文件>把新文件纳入版本控制，否则提交时会被跳过

          
svn commit -m "说明"提交到版本库，版本号 +1。缩写 ci，不写 -m 会弹编辑器

          
svn diff [文件]看具体改了哪几行；-r 5:7 比较任意两个版本

        


        
状态字母的含义

        

          
?未纳入版本控制（新建的文件，需要 add）

          
A / D已标记为新增 / 删除，等待提交

          
M已修改，等待提交

          
C冲突，必须手工处理后 resolve

          
!文件不见了（被资源管理器直接删掉了），用 svn revert 找回

          
*（配合 -u）服务器上有更新的版本，你已过期

        


        
撤销与救命

        

          
svn revert <文件>丢弃本地改动还原文件；-R . 递归全部还原。改动无法找回

          
svn resolve --accept working <文件>手工改完冲突后，告诉 SVN 已解决

          
svn merge -c -6 .撤销已提交的 r6（注意负号），再 commit 一次

          
svn cleanup工作副本被锁住（previous operation has not finished）时执行

          
svn log -l 5 -v看最近 5 条提交历史，-v 显示每次改了哪些文件

        


        
分支与标签

        

          
svn copy ^/trunk ^/branches/xx -m "说明"建分支 = 服务器端拷贝目录，^/ 指版本库根

          
svn switch ^/branches/xx把现有工作副本切到分支，不用重新检出

          
svn merge ^/branches/xx在 trunk 工作副本里执行，把分支改动合并进来，检查后再提交

          
svn copy ^/trunk ^/tags/v1.0 -m "发布"打标签，约定 tags 下的内容不再修改
